# Obsidian CF Sync

Obsidian CF Sync is a prototype single-user Obsidian vault sync system backed by Cloudflare Workers, Durable Objects with SQLite storage, and R2 chunk storage.

The expected deployment model is self-hosted: one person deploys their own isolated Cloudflare Worker, R2 bucket, and Durable Object namespace, then pairs their own Obsidian devices to that instance.

The app has three workspace packages:

- `packages/protocol`: shared Effect schemas and HTTP API contract.
- `packages/worker`: Cloudflare Worker entrypoint plus the `VaultDO` Durable Object.
- `packages/plugin`: Obsidian plugin that watches vault files, chunks content, and syncs with the Worker.

`PLAN.md` contains the broader product and architecture plan. The docs in `docs/` describe the code that exists today.

## Current Status

This is a working prototype, not a production-ready Obsidian Sync replacement.

Implemented today:

- Shared request/response schemas for sync protocol payloads.
- Authenticated Worker routes for prepare, commit, changes, index, chunk upload, and chunk download.
- Per-vault Durable Object state using DO SQLite.
- R2-backed content-addressed chunk storage.
- Obsidian plugin settings for Worker URL, vault ID, API key, and sync interval.
- File create/modify/delete handling in the plugin.
- Fixed-size 256 KB chunking in the plugin.
- WebSocket connection and broadcast path for remote change notifications.
- IndexedDB local state for file metadata, pending operations, sync state, and chunk cache.
- Device enrollment with per-device sync tokens.
- Device revocation through the bootstrap API key.
- Exact file-version compare-and-swap for every mutation.
- Immutable attempted operations, ordered successors, and server-side rejection of operation-ID reuse with a changed payload.
- Resumable remote imports, tombstone-aware fresh clients, and verified chunk downloads.
- Immediate disable/reconfiguration, receive-side configuration-directory exclusion, and device revocation that closes existing sockets.
- Atomic, idempotent rename operations in one Durable Object transaction.
- Vault-scoped authorization for chunk downloads, even though R2 deduplicates
  physical chunk bodies globally.
- Worker integration tests using `@cloudflare/vitest-pool-workers`.
- Simulated-client E2E tests against local Worker/DO/R2, with controlled delays, offline clients, and lost acknowledgements (`pnpm test:e2e`). Recovery scenarios include interrupted bootstrap, lost acknowledgements, and subsequent edits.
- Plugin unit tests for local state isolation and WebSocket lifecycle safety.

Not implemented or incomplete:

- End-to-end encryption.
- Production-grade device approval UX and key rotation.
- Conflict UX beyond creating local conflict copies and notices.
- A user-directed reconciliation flow when a fresh local vault and remote
  vault both already contain files. Sync safely pauses and reports a summary.
- Garbage collection for unreferenced R2 chunks.
- Presigned download/upload URLs. The Worker currently proxies chunk upload and download.

## Requirements

- Node.js 22.12+ (or 20.19+).
- `pnpm` 10.33.0.

## Setup

Install dependencies:

```sh
pnpm install
```

Run checks:

```sh
pnpm check
pnpm lint
pnpm typecheck
pnpm test
```

Run the Worker locally:

```sh
pnpm dev:worker
```

Build the Obsidian plugin:

```sh
pnpm build:plugin
```

The build output in `packages/plugin/dist` contains the installable Obsidian plugin files:

- `main.js`
- `manifest.json`
- `styles.css`

Set `SYNC_API_KEY` in an ignored local `.env` file, then deploy with Alchemy:

```sh
pnpm deploy --stage prod
```

Plan or destroy the Alchemy stack:

```sh
pnpm plan
pnpm destroy
```

## Configuration

The Worker expects these bindings:

- `CHUNKS_BUCKET`: R2 bucket used for chunk bodies.
- `SYNC_API_KEY`: bootstrap bearer token used for device enrollment and revocation.
- `VaultDO`: Durable Object namespace for per-vault metadata and coordination.

`wrangler.toml` defines the local Worker entrypoint, R2 binding, Durable Object binding, and SQLite Durable Object migration.

`alchemy.run.ts` provisions the R2 bucket, Worker, secret, and Durable Object binding for deploys through Alchemy.

## Plugin Configuration

In Obsidian settings, configure:

- Worker URL: deployed Worker URL, for example `https://obsidian-cf-sync.example.workers.dev`.
- Vault ID: stable identifier for the vault. This determines the Durable Object instance.
- API Key: bootstrap key matching `SYNC_API_KEY`, used to pair/re-pair this device.
- Device token: generated by the Worker when the plugin pairs this device. Sync traffic uses this token.
- Sync enabled: whether sync starts automatically when settings are complete.
- Sync interval: debounce interval in milliseconds for local file changes.

The plugin generates a `deviceId` on first load and stores settings through Obsidian plugin data. Use the settings tab's `Pair device` button after configuring Worker URL, vault ID, and API key.

## Single-User Install Flow

1. Deploy your own Worker stack with `pnpm deploy`.
2. Build the plugin with `pnpm build:plugin`.
3. Copy `packages/plugin/dist` into your vault at `.obsidian/plugins/obsidian-cf-sync`.
4. Enable the plugin in Obsidian community plugin settings.
5. Enter the Worker URL, vault ID, and bootstrap API key.
6. Click `Pair device`.
7. Repeat plugin install and pairing on each personal device that should sync the vault.

After pairing, sync uses the generated device token. The bootstrap API key is only needed to pair or re-pair a device.

## Install a released plugin

Download `main.js`, `manifest.json`, and `styles.css` from a
[GitHub release](https://github.com/peculiarnewbie/obsidian-cf-sync/releases).
Create `<vault>/.obsidian/plugins/obsidian-cf-sync/`, copy the three files there,
restart Obsidian, and enable **Obsidian CF Sync** under Community plugins.
Then configure your Worker URL and vault ID, and pair using your bootstrap key.

The initial `0.1.0` release is a prerelease for testing on backed-up vaults.
It is not listed in Obsidian's community directory. The GitHub-generated
source archives are source code, not the installable plugin.
